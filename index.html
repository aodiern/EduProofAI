Платеж возникает при AI-проверке, выпуске NFT-сертификата и платной API-верификации. Для учебного MVP комиссия считается в EDP, чтобы показать токеномику без фиатного биллинга.

За что платят AI-анализ + доказуемая сертификация

Пользователь получает не просто процент оригинальности, а проверяемый результат: workHash, reportHash, IPFS metadata и NFT-запись в blockchain registry.

Зачем токен Связывает спрос, качество и децентрализацию

EDP оплачивает вычисления, мотивирует валидаторов хранить и проверять metadata, а burn снижает обращающееся предложение при росте количества проверок.

Мотивация для инвесторов и участников

Если число проверок растет, увеличиваются комиссии, объем burn и спрос на stake валидаторов. Вузам выгодно подключаться, потому что сертификаты становятся переносимыми между платформами, а проверяющим не нужен доступ к закрытому тексту работы.

  • EDP оплачивает AI-проверки, выпуск сертификатов и доступ к API верификации.
  • Сжигание части комиссии снижает обращающееся предложение при росте спроса.
  • Валидаторы получают вознаграждение за подтверждение хешей и доступности metadata.
  • Казначейство финансирует гранты вузам и развитие AI-моделей.

Positioning

Отличия от конкурентов

Обычный антиплагиат Находит текстовые совпадения и показывает процент похожести. Обычно не доказывает, что именно этот отчет существовал в конкретный момент времени.
Turnitin и аналоги Имеют сильные базы источников, но работают как централизованный сервис: результат зависит от доступа к платформе и не является переносимым NFT-сертификатом студента.
EduProof AI Объединяет AI-рецензию, антиплагиат, IPFS metadata, хеш работы и запись в смарт-контракте. Проверяющему не нужен доступ к исходному тексту.
Критерий Классический сервис EduProof AI
Доказуемость результата Отчет хранится внутри сервиса, внешняя проверка ограничена. Хеш отчета и metadata URI фиксируются в реестре, результат можно проверить по Token ID.
Приватность работы Часто требуется загрузка полного текста в закрытую базу платформы. В блокчейн попадают только хеши и ссылка на metadata, полный текст не публикуется.
Переносимость сертификата Студент зависит от аккаунта в конкретной системе. NFT-сертификат можно показать вузу, работодателю или грантовой комиссии без раскрытия работы.
AI-оценка качества Фокус обычно на похожести текста. Дополнительно оцениваются структура, стиль автора, риск генерации и рекомендации по доработке.
Экономика платформы Оплата идет оператору сервиса. EDP распределяет комиссию между burn, валидаторами и treasury для развития AI-моделей.
System design

Архитектура платформы

Browser форма работы, кошелек, проверка сертификата
Backend API антиплагиат, хеши, orchestration
AI-модель Ollama или OpenAI-compatible рецензент
IPFS -> Smart Contract metadata, mint, blockchain registry

Frontend

Статическое приложение на HTML/CSS/JS. Демо-алгоритм формирует отчет и локальный NFT-реестр через localStorage.

Backend stage

Node.js API принимает файлы, вызывает AI-модель, пишет metadata в IPFS и отправляет транзакцию mint от имени авторизованного вуза.

Blockchain

Контракт хранит tokenId, хеш студента, хеш работы, хеш AI-отчета, балл и статус отзыва сертификата.

Ролевая модель

Студент отправляет работу, issuer выпускает сертификат, проверяющий валидирует запись, администратор управляет демо-состоянием и политиками.

Detailed data flow

Как проходит одна проверка

  1. 01
    Browser -> Backend API

    Студент вводит автора, вуз, название и текст работы. Клиент отправляет JSON-заявку в `/api/analyze-work`, а интерфейс сразу показывает текущий этап pipeline.

  2. 02
    Backend orchestration

    Сервер нормализует текст, считает `workHash`, запускает локальный антиплагиат по шинглам и готовит запрос к AI-модели.

  3. 03
    AI-модель

    Ollama или OpenAI-compatible модель оценивает оригинальность, академическую структуру, стиль автора и риск искусственной генерации. Если модель недоступна, включается локальная эвристика.

  4. 04
    IPFS metadata

    Backend формирует `reportHash` и metadata JSON: баллы, краткий AI-отчет, совпадения, CID и ссылку `ipfs://...`. Полный текст работы в блокчейн не записывается.

  5. 05
    Smart Contract

    Контракт `EduProofCertificate` выпускает NFT-сертификат и сохраняет `studentHash`, `workHash`, `reportHash`, `metadataURI`, итоговый балл и статус отзыва.

  6. 06
    Blockchain Registry

    Транзакция попадает в реестр. Преподаватель, вуз или работодатель проверяет Token ID, сверяет хеши и видит, что сертификат не был отозван.

On-chain Минимум публичных данных

Token ID, хеши, score, metadata URI, issuer, owner и флаг revoked. Это дает проверяемость без публикации исходной работы.

Off-chain AI-отчет и metadata

IPFS-слой хранит отчет и доказательства проверки. В MVP это совместимое локальное хранилище `storage/ipfs`, дальше его можно заменить на Pinata/Web3.Storage.

Fallback Демо работает без внешних сервисов

Если Ganache или Ollama не запущены, приложение сохраняет результат в локальный registry и использует встроенную модель оценки, чтобы защита проекта не ломалась.

Verification Проверка подлинности

Проверяющий вводит Token ID или хеш работы. Система находит сертификат, показывает статус, балл, issuer, CID и transaction hash.

Project plan

Roadmap

Phase 01 Фундамент MVP готово

Собрать приложение в одном репозитории и сделать демонстрационный сценарий без внешних зависимостей.

UI проверки Node.js API локальный registry отчет AI
Критерий: пользователь загружает текст, получает score, hash и NFT-preview.
Phase 02 AI + антиплагиат текущий этап

Усилить проверку учебных работ: локальная нейросеть, корпус источников, совпадения по шинглам и объяснимый отчет.

Ollama model 5-shingles plagiarism risk fallback heuristics
Критерий: отчет показывает оригинальность, найденные источники, структуру и причину выставленного балла.
Phase 03 Smart Contract + Ganache локально готово

Truffle/Ganache уже подключены: контракт компилируется и деплоится из этого репозитория, backend умеет делать mint через Ganache RPC. Если Ganache не запущен, включается fallback registry. Следующий шаг после локальной сети - Polygon Amoy и MetaMask.

EduProofCertificate Ganache RPC Truffle migrate contract mint
Критерий: при запущенном Ganache и выполненной migration Token ID, tx hash и metadataURI приходят из реального вызова контракта.
Phase 04 IPFS и приватность инфраструктура

Разделить публичные и приватные данные: в блокчейн пишутся только хеши, а отчет и metadata закрепляются в IPFS.

Pinata/Web3.Storage CID pinning metadata schema content privacy
Критерий: проверяющий может сверить сертификат без доступа к полному тексту работы.
Phase 05 Авторизация и роли безопасность

Заменить демо-переключатель роли на настоящую авторизацию: вход через аккаунт вуза или MetaMask, проверка роли на backend и сверка issuer/admin-прав со смарт-контрактом.

login / wallet sign JWT session role middleware issuer registry
Критерий: студент не может выпустить NFT, проверяющий не может изменить реестр, а issuer подтверждается backend-сессией и контрактом `onlyIssuer`.
Phase 06 Пилот с вузом валидация рынка

Запустить ограниченный пилот для кафедры: преподаватель создает проверки, студент видит результат, внешний проверяющий подтверждает сертификат.

кабинет преподавателя batch upload API verify consent flow
Критерий: 30-50 работ проходят проверку, а сертификаты можно независимо найти в реестре.
Phase 07 Production и токеномика масштабирование

Подготовить аудит, мониторинг, EDP-экономику, роли валидаторов и публичную документацию для подключения новых вузов.

security audit token rules monitoring partner docs
Критерий: платформа может обслуживать несколько организаций и проверяемые публичные сертификаты.
